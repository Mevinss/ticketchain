# TicketChain

Учебный сервис билетов: каталог → место → покупка → QR-билет → проверка входа. React/TypeScript/Vite, ethers v6, RU/KZ. Контракт Solidity 0.8.24 без внешних зависимостей. Использовать тестовый ETH.

## Быстрый запуск сайта

Требуется Node.js 22 LTS или новее и npm.

```powershell
npm ci
Copy-Item frontend/.env.example frontend/.env
npm run dev
```

Откройте напечатанный Vite адрес. Без адреса контракта видны инструкция настройки и явно отмеченные примеры афиши. Настоящих билетов в этом режиме нет.

В `frontend/.env` укажите `VITE_CHAIN_ID`, `VITE_RPC_URL`, `VITE_CONTRACT_ADDRESS`, `VITE_EXPLORER_URL`. `.env.local` имеет приоритет: уберите локальную конфигурацию перед переходом на Sepolia. После изменения env перезапустите dev-сервер; для публикации выполните новую сборку.

## Контракт и Remix

Полная инструкция с полями и двумя сценариями: [docs/REMIX-DEPLOY.md](docs/REMIX-DEPLOY.md).

Constructor не имеет аргументов. Deploy с Value 0. Деплоер становится admin.
Compiler 0.8.24, EVM London, optimizer off. Ветка содержит исправленные артефакты ABI, экспортированные компилятором. Исходная логика TicketChain.sol сохранена.

```powershell
npm run compile
npm test
npm run build
```

Компиляция обновляет `artifacts/` и ABI frontend. Тесты: 11 проверок frontend и 28 локальных EVM-проверок, включая разные роли, reentry, отказ получателя и откат состояния. На Node 24 Ganache может сообщить о переходе с native µWS на JS: это предупреждение о производительности, не результат теста.

Старый `scripts/run_ticketchain_tests.ts` заменен воспроизводимым `npm run test:contract`; в старом использовались ethers v5 и неподтвержденный API перемотки времени. Для плагина Solidity Unit Testing используйте `tests/RemixTicketChain_test.sol`. Его фактический запуск в вашей Remix VM — отдельный ручной шаг, не следует считать локальные Ganache тесты результатом Remix.

## Локальная интеграция без кошелька Sepolia

```powershell
npm run local:chain -- --write-env
```

В другом терминале: `npm run dev -- --port 5173 --strictPort`.
Создаются локальная сеть 31337, контракт, 6 реальных событий только в этой локальной сети и роли. Запись находится в игнорируемом `.superpowers/local-deployment.json`. Приватные ключи не записываются. `--write-env` создает игнорируемый `frontend/.env.local` и отказывается перезаписывать существующий файл. Без флага настроить env можно вручную.

Для UI-проверки с установленным Edge: `node scripts/browser-check.cjs`. Скрипт использует тестовый injected provider к локальной EVM, а не MetaMask. На свежем локальном узле он проходит покупку, билет, смену аккаунта, вход, отмену, возврат и казахскую локализацию. Скриншоты сохраняются в `.impeccable/review/`. Состояние тестовой сети меняется: для повторного полного сценария используйте свежий локальный узел.

## Metadata и публикация

В `frontend/public/metadata` находятся 6 примеров JSON, в `frontend/public/posters` — собственные типографические SVG. Они входят в `dist` при сборке; на хостинге будут доступны по `/metadata/night.json` и `/posters/night.svg`. Относительные ссылки на постеры разрешаются относительно URL metadata. Эти файлы не создают on-chain события автоматически.

В admin-панели можно скачать JSON, разместить его самостоятельно и проверить опубликованный URL. Затем создать событие через кошелек. Для Sepolia используйте публичный HTTPS URL, а не localhost.

`npm run build` создает `dist/`. Любому статическому хостингу нужен SPA fallback на `index.html` для `/events/*`, `/tickets/*`, `/admin`, `/check-in`, `/my-tickets`. Для Netlify включен `_redirects`; для Vercel — `vercel.json`. Публикация здесь не выполняется автоматически. Env в Vite публичны: секреты туда не помещать.

## Ограничения

- Нет mainnet, банковских карт, перепродажи и временного резервирования мест.
- QR — публичный ID. Проверяющий сверяет владельца отдельно.
- Метаданные находятся вне блокчейна; при их недоступности доступны основные on-chain данные.
- Средства организатор получает только после конца события; отмена возможна до открытия входа за час до начала.
- Если наблюдение транзакции прервано, hash сохраняется, статус остается ожидающим. Кнопка проверки статуса обращается к фиксированному RPC исходной сети; повторные записи блокируются до результата.
- Sepolia deploy, реальные события и проверка с MetaMask требуют действий и подписи владельца кошелька. Не вводите seed phrase в сайт или исходники.

## Состав

- `contracts/TicketChain.sol`: правила и деньги.
- `scripts/compile-contract.cjs`: воспроизводимая сборка ABI.
- `tests/contract`: реальные транзакции локальной EVM и злонамеренный/отказывающий получатель.
- `frontend/src/lib`: типы, данные, RPC, проверки QR/дат, мониторинг транзакций.
- `frontend/src/context`: язык, кошелек, транзакции.
- `frontend/src/pages`: шесть пользовательских экранов.
- `docs/CONTRACT-API.md`: соответствие UI и контрактных вызовов.
